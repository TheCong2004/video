## 1. Outcome and boundaries

The user works in Concat to create AI content, import generated media, edit it,
and eventually publish it. Promax remains the orchestration backend. ArtCraft's
engines remain services rather than being copied into the editor or rewritten.

User constraints: current low-power Windows machine; preserve working editing;
move the production navigation beneath Media; avoid redundant application code.

Do not delete ArtCraft, models, user media, history, profiles, credentials, or
databases during migration. Do not start cloud services, pay for generation,
publish content, or migrate authentication implicitly. Installing a native menu
does not make its backend workflows available.

## 2. Verified starting points

- Concat window: Rust + Slint, `src/crates/concat`.
- Library: `ui/workspace/media-pane.slint`; multiple library seats are supported.
- Existing import: `Editor.import-media` -> `MediaMsg::Import` -> background
  probing -> project AddMedia commands. Reuse this path, including undo/project
  scoping; do not add a second media database.
- Host services: `src/crates/concat-host`; existing HTTP dependency is ureq 2.
- Source production navigation: ArtCraft
  `frontend/apps/artcraft/app/src/pages/FlowordStudio/src/components/FlowordSidebar.tsx`.
- Source workflows use both Tauri commands and HTTP; React components cannot be
  pasted into Slint. Inventory each action before porting it.
- ArtCraft unified backend is normally loopback port 30000; OpenTalking 18100.
- Promax readiness routes include `/health/ready`. Ports are deployment-specific.
- Concat retains upstream licence/notices. Distribution/licensing review remains
  a release gate; this document does not give legal advice.

## 3. Navigation and view ownership

Keep Media/Generated filters and their counts intact. Beneath them add collapsible
groups. A selected Studio route replaces only the library's browsing area, not
the timeline, monitor, inspector, project or playback state.

Each route must show its actual migration/capability status. No fake green

resizable sidebar. Sidebar and content scroll independently.

## 4. Architecture and contracts

1. Slint renders view models and emits user intent only.
2. A Rust Studio controller owns request state, cancellation, credentials handles,
   selected backend and project association; never block Slint callbacks on I/O.
3. Host adapters own bounded HTTP calls and typed response parsing.
4. Promax owns orchestration/job state. ArtCraft/OpenTalking own media engines.
5. Completed files enter the existing Concat media import pipeline.

Phase 1 checks only local loopback services, on explicit click. No background
polling on editor startup, no redirects, credentials, generation, process start,
or process termination. Health response bodies are bounded; HTTP 200 alone does
not prove a model is ready. Display transport reachability separately from
workflow/engine readiness.

Later contracts (confirm against source handlers before implementation):

- CapabilityReport: service identity/version, supported operations, engine state.
- JobSummary: provider job ID, state, progress if genuinely reported, timestamps.
- Artifact: stable ID, media kind, source, size, content digest where available.
- Error: safe user-facing category, retryable flag, internal correlation ID.
- Session: account identity and token lifecycle without moving raw keys into UI.
